
# AeroForge Precision Components — Part 1: AWS Logical Architecture Walkthrough, Service Rationale & Defense Guide

## 1. End-to-End Numbered Flow Walkthrough (Flows 1–32)

1. **MQTT Telemetry (`s1_edge` -> `i1_iot`):** Shop-floor machines (CNC mills, drills, autoclaves, furnaces, and CMMs) publish OPC UA sensor readings through local AWS IoT Greengrass gateways, which strip operator IDs at the edge and buffer up to 15 minutes locally to protect the telemetry RPO. Gateways transmit mutually authenticated TLS 1.2+ MQTT payloads over Site-to-Site VPN or Direct Connect via AWS Transit Gateway into AWS IoT Core. In the Data Pack, this stream is represented by `telemetry_hourly.csv` (8,632 hourly rows across 12 machines from `machines.csv`), capturing `spindle_rpm`, `vibration_mm_s`, `temp`, `temp_unit`, and `power_kw`.

2. **IoT Rules (`i1_iot` -> `i2_kds`):** AWS IoT Core terminates gateway X.509 certificates and evaluates IoT Rules to route incoming telemetry messages to Amazon Kinesis Data Streams without exposing shop-floor networks to the public internet. Messages are partitioned by `machine_id` so per-machine event ordering is preserved across the 3-plant pilot (600 machines) and 12-plant enterprise target (2,400 machines).

3. **Stream — 20K msg/s Burst (`i2_kds` -> `i3_flink`):** Amazon Kinesis Data Streams runs in On-Demand mode as a durable, Multi-AZ log buffer sized for 20,000 msg/s peak bursts (~20 MB/s) against an enterprise average of 480 msg/s. It fans out the live telemetry stream simultaneously to Amazon Data Firehose for durable raw landing and to Amazon Managed Service for Apache Flink for sub-minute anomaly detection.

4. **Micro-batch JSONL.gz (`i3_flink` -> `l1_raw`):** Amazon Data Firehose micro-batches incoming telemetry every 60 seconds, compresses payloads as GZIP (`JSONL.gz`), and writes them immutably into `raw/iot_telemetry/` in the S3 Bronze zone. While the enterprise design targets ~1.5 TB/month of nested JSONL.gz events, the Data Pack provides hourly CSV aggregates in `telemetry_hourly.csv` for prototype validation.

5. **Under-60s Anomaly Alert (`i3_flink` -> `in2_alerts`):** Amazon Managed Service for Apache Flink executes stateful streaming anomaly detection (Random Cut Forest and vibration threshold checks) directly over the Kinesis stream. When a critical machine condition—such as a Criticality A CNC exceeding 1.5x vibration baseline under `SOP-MX-002`—is detected, a Flink Lambda sink publishes an alarm to Amazon SNS and EventBridge within 60 seconds so cell leads can inspect the asset and apply 72-hour quality containment under `SOP-MX-014`.

6. **SQL CDC (`s2_mes` -> `i4_dms`):** On-premises SQL Server MES databases stream transaction-log Change Data Capture (CDC) for production work orders (~60,000/month enterprise; `mes_work_orders.csv`, 203 rows in the Data Pack) and asset/part/material master tables (`machines.csv`, `parts.csv`, `materials.csv`) to AWS DMS Serverless. Crucially, MES CDC from all plants—including Querétaro (QRO)—travels over private VPN/Direct Connect directly to `us-east-1` and never lands in `mx-central-1`, which is strictly isolated to Mexican HR, payroll, and employee PII. When DMS ingests QRO work orders referencing ITAR-controlled TALON parts (`P-1002` or `P-1003` in `parts.csv`, such as `WO-00005` running `P-1003` on `QRO-CNC-01`), DMS task routing and bucket policies direct those records exclusively into the dedicated US TALON account (`us-east-1`, DR in `us-west-2`), satisfying `SOP-SEC-001`.

7. **CMMS REST API (`s3_cmm` -> `i4_dms`):** Amazon AppFlow (or a scheduled AWS Lambda custom connector) polls the SaaS CMMS REST API hourly to extract preventive and corrective maintenance work orders (~4,000/month enterprise) along with technician free-text repair notes. In the Data Pack, `cmms_maintenance_orders.csv` (25 rows) represents this feed, including `MO-0001` (corrective spindle bearing failure on `WIC-CNC-02` with 44 downtime hours, $6,200 labor, and $18,400 parts) and scheduled PM orders (`MO-0002`–`MO-0005`) following `SOP-MX-002`.

8. **CMM CSV via SFTP (`s3_cmm` -> `i5_transfer`):** Coordinate-Measuring Machine (CMM) inspection software exports dimensional tolerance measurements (~150,000 CSV measurements/month enterprise) over SFTP to VPC-hosted AWS Transfer Family. The enterprise pipeline lands these files under `raw/quality/inspections/` to correlate part defects with machine health; the Data Pack does not include sample CMM inspection files.

9. **ERP Nightly SFTP (`s4_erp` -> `i5_transfer`):** The corporate on-premises ERP exports nightly General Ledger, Accounts Payable, budget, standard cost, and master CSV extracts (~2M GL lines/month enterprise) at 23:00 CT via AWS Transfer Family SFTP. In the Data Pack, this feed corresponds to `erp_gl_journal_lines.csv` (766 rows), `erp_ap_invoices.csv` (46 rows), `finance_budget_sep2026.csv` (30 rows), `plants.csv` (3 rows), and `suppliers.csv` (3 rows).

10. **REST APIs & SOPs (`s5_ext` -> `i5_transfer`):** EventBridge-scheduled AWS Lambda functions call the Open-Meteo daily plant weather API (`weather_daily_sample.csv`, 90 fallback rows), daily commodity price (`TITANIUM_TI64`, `ALUMINUM_7075`) and `USD_MXN` FX APIs (`market_prices_api_sample.json`), and incremental SharePoint Online syncs for engineering SOPs (~20,000 enterprise documents; 4 Markdown files in `sop/*.md`). Credentials and API tokens are retrieved securely at runtime from AWS Secrets Manager.

11. **De-identified MXN GL Rollups Only (`b_mexico` -> `i5_transfer`):** Inside the dedicated AWS Mexico account (`mx-central-1`), QRO employee HR, payroll, timecards, and PII remain encrypted in local S3 under KMS CMK #3 and never leave Mexico; the Data Pack contains no HR or payroll sample files. Only an allow-listed export gate (Lambda/Glue) transmits de-identified MXN GL cost rollups across the border to the US ingestion tier for corporate financial consolidation.

12. **CDC & CMMS Land (`i4_dms` -> `l1_raw`):** AWS DMS Serverless and the CMMS connector write raw, append-only MES production orders (`raw/mes/production_orders/`), master data (`raw/master/`), and CMMS maintenance orders (`raw/cmms/maintenance_work_orders/`) into the S3 Bronze zone. Landing raw payloads unmodified preserves full replayability and audit lineage before any transformation runs.

13. **Batch CSV, JSON & SOPs (`i5_transfer` -> `l1_raw`):** AWS Transfer Family and ingestion Lambda functions land ERP financial extracts (`raw/erp/`), CMM inspection CSVs (`raw/quality/inspections/`), weather and market JSON (`raw/external/`), and SOP Markdown/PDF files (`docs/sop/`) into S3 Bronze. Raw telemetry follows a 2-year lifecycle tiering policy, while ERP financial files carry 7-year S3 Object Lock retention to satisfy SOX audit requirements.

14. **Read Raw (`l1_raw` -> `l2_glue`):** EventBridge triggers AWS Step Functions to launch AWS Glue ETL (Spark) and Glue Data Quality jobs against newly landed S3 Bronze partitions, with Amazon EMR Serverless reserved for heavy historical backfills. Glue job bookmarks and deterministic hashing ensure idempotent processing across hourly operational runs and nightly financial batches.

15. **DQ Rejects (`l2_glue` -> `l3_quarantine`):** Automated Glue Data Quality rules evaluate every dataset against explicit schema, completeness, and uniqueness thresholds and route failing records—never dropping them—into the S3 Quarantine bucket with error metadata. Specifically, GL journal lines missing a `cost_center` in `erp_gl_journal_lines.csv` and duplicate AP invoices sharing `(supplier_id, supplier_invoice_no)` in `erp_ap_invoices.csv` are quarantined for steward remediation and replay, triggering an immediate SNS notification.

16. **Write Validated Silver (`l2_glue` -> `l4_curated`):** Clean, deduplicated records are written to the S3 Curated (Silver) zone in Parquet/Iceberg format after standardized cleansing. This step converts Fahrenheit gateway readings to Celsius using `temp_unit` in `telemetry_hourly.csv`, handles late-arriving and missing telemetry windows (such as the 8,632 observed rows vs. 8,640 expected), standardizes inconsistent labels (mapping `usd_per_kg` for `USD_MXN` in `market_prices_api_sample.json` to an explicit FX rate column), and normalizes MXN amounts to USD while preserving original currency values.

17. **Conform Gold Star Schema (`l4_curated` -> `l5_gold`):** AWS Glue ETL (Spark) conforms validated Silver entities into the Plant-to-P&L Star Schema in the S3 Gold zone using Apache Iceberg (S3 Tables), establishing AWS as the single authoritative finance and operations system of record. Gold facts (Telemetry/OEE, Production/Scrap, Maintenance, GL/AP/Budget, Market/Weather) and conformed dimensions (Plant, Machine, Part/Material/Program, Supplier, CostCenter/GL, Date) are refreshed hourly for operations and guaranteed ready by 07:00 CT daily for finance, supporting ACID time-travel for SOX audits. TALON records remain physically segregated in the dedicated US TALON account (`b_talon`) encrypted with KMS CMK #2 and governed by Lake Formation filters (`program <> 'TALON'`).

18. **External Schema Read In-Place (`l5_gold` -> `sv1_redshift`):** Amazon Redshift Serverless mounts the S3 Gold Apache Iceberg tables in place via an external schema registered in the AWS Glue Data Catalog, eliminating data duplication and ensuring Redshift never becomes a second copy of financial truth. Redshift enforces Row-Level Security and user identity propagation, serves governed semantic views for OEE, scrap rate, PPV, and budget variance, and maintains aggregate-only commercial materialized views for sub-second dashboard concurrency.

19. **SQL-on-Lake (`l5_gold` -> `sv2_athena`):** Amazon Athena provides serverless SQL-on-lake access across Gold, Silver, Raw, and Quarantine S3 zones, honoring AWS Lake Formation tag-based permissions and cell filters. Data engineers and SOX auditors use Athena workgroups (with per-query scan caps) to inspect quarantined records, compute Data Quality scores, and execute Iceberg time-travel audit queries.

20. **Training & Features (`l4_curated` -> `sv3_sagemaker`):** VPC-only Amazon SageMaker AI Pipelines read cleaned Silver entity tables to engineer rolling sensor, work-order, and cost features into SageMaker Feature Store. Models are trained with strict chronological train/validation/test splits to prevent temporal leakage and evaluated on business-cost-weighted PR-AUC/F-Beta metrics across five use cases: 48-hour predictive maintenance, streaming anomaly detection (deployed to Flink), work-order scrap risk, energy/titanium cost forecasting, and SHAP variance driver analysis.

21. **Batch Predictions & SHAP (`sv3_sagemaker` -> `l5_gold`):** Scheduled SageMaker batch transform jobs write work-order scrap risk scores, energy and titanium PPV forecasts, and SHAP variance attributions back into dedicated S3 Gold Iceberg tables. Storing model outputs in Gold links predictive insights directly to GL cost centers and work orders for 07:00 CT controller reporting and `SOP-FIN-003` variance explanations (>15% MTD variance).

22. **Live 48h Risk Scores (`sv3_sagemaker` -> `sv4_dynamodb`):** SageMaker inference pipelines publish updated per-machine 48-hour failure probabilities and health bands into Amazon DynamoDB for single-digit millisecond lookup. Maintaining live risk state in DynamoDB decouples real-time operational queries and AI agent lookups from analytical warehouse workloads.

23. **Zero-Copy Read (`l5_gold` -> `l6_part2_hook`):** The S3 Gold Apache Iceberg layout exposes a read-only, zero-copy multi-cloud interface strictly scoped to commercial, non-TALON prefixes via Lake Formation grants and scoped IAM policies. External analytics platforms can read authoritative Gold tables in place without creating a third physical copy, while TALON tables in `b_talon` remain completely blocked from cross-cloud access.

24. **Governed BI Queries (`sv1_redshift` -> `in1_quicksight`):** Amazon QuickSight connects to Amazon Redshift Serverless to power hourly-refreshed Plant Manager, Maintenance Lead, and Plant Controller dashboards as well as the automated daily 07:00 CT Plant-to-P&L executive brief. Row-Level Security tied to IAM Identity Center ensures plant users see only their authorized sites and non-US persons never view TALON parts or costs.

25. **Ad-hoc & DQ Metrics (`sv2_athena` -> `in1_quicksight`):** QuickSight also queries Amazon Athena to display live Data Quality scorecards, quarantine record counts, and pipeline freshness metrics directly alongside operational KPIs. Surfacing DQ health next to financial variances gives controllers immediate confidence in the underlying `erp_gl_journal_lines.csv` and `erp_ap_invoices.csv` totals.

26. **SOP Docs & CMMS Notes Sync (`l1_raw` -> `in3_kb`):** Amazon Bedrock Knowledge Bases indexes engineering SOPs from `docs/sop/` (`SOP-FIN-003`, `SOP-MX-002`, `SOP-MX-014`, `SOP-SEC-001` in the Data Pack; ~20,000 enterprise documents) and CMMS technician repair notes (`technician_note` in `cmms_maintenance_orders.csv`) into Amazon OpenSearch Serverless vector collections. Metadata tagging and account segregation keep TALON-specific procedures isolated from commercial vector indices.

27. **Grounded RAG + Guardrails (`in3_kb` -> `in4_agentcore`):** When users query Amazon Bedrock AgentCore (powered by Anthropic Claude), Bedrock Knowledge Bases supplies cited SOP and repair-note context while Bedrock Guardrails filter out PII, off-topic prompts, and unsafe outputs. Grounding ensures the Maintenance Advisor cites exact thresholds such as the 250-run-hour PM interval (`SOP-MX-002`) and 72-hour quality hold rule (`SOP-MX-014`).

28. **Text-to-SQL MCP Tool (`sv1_redshift` <-> `in4_agentcore`):** The Variance Analyst and Supply & Cost agents invoke AgentCore Gateway MCP tools (backed by AWS Lambda and the Redshift Data API) to run governed SQL against Redshift's semantic views. AgentCore Identity propagates the authenticated user's token end to end with zero standing privileges, so Redshift and Lake Formation automatically enforce plant scoping and TALON US-Person restrictions (`SOP-SEC-001`) while tracing >15% variances (`SOP-FIN-003`) or titanium PPV (`materials.csv`, `erp_ap_invoices.csv`, `market_prices_api_sample.json`).

29. **Live Risk State Lookup (`sv4_dynamodb` <-> `in4_agentcore`):** The Maintenance Advisor agent calls an AgentCore Gateway MCP tool to retrieve sub-10ms live machine health and 48-hour failure risk scores from Amazon DynamoDB. Combining live risk scores with RAG SOP retrieval lets the agent immediately identify high-risk assets and recommend prescribed containment actions.

30. **Draft P1 CMMS Work Order (`in4_agentcore` -> `in5_hitl`):** When a user or triage workflow requests a corrective action—such as opening a P1 maintenance work order—Bedrock AgentCore drafts a structured work-order payload but cannot write directly to external systems. Instead, it routes the draft into a mandatory AWS Step Functions Human-in-the-Loop (HITL) approval gate requiring explicit supervisor sign-off.

31. **Approved Action: Audit Log & CMMS Dispatch (`in5_hitl` -> `sv4_dynamodb`):** Once an authorized supervisor approves the drafted P1 work order, Step Functions invokes the Gateway Lambda to dispatch the order to the SaaS CMMS API and writes an immutable record of caller identity, approver identity, timestamp, and payload to DynamoDB and CloudTrail. Unapproved requests time out safely with zero shop-floor impact.

32. **Notify Cell Lead (`in5_hitl` -> `in2_alerts`):** Simultaneously upon supervisor approval, the HITL workflow publishes a notification through Amazon SNS to the responsible shop-floor cell lead. This closes the Plant-to-P&L digital thread by alerting operators to inspect the machine and initiate any required 72-hour quality holds under `SOP-MX-014`.

## 2. Two-Minute Spoken Explanation

"AeroForge's problem is fragmentation: sensor warnings happen on the shop floor, work orders live in SQL Server MES, repairs sit in a SaaS CMMS, and finance closes the books nine days late in an on-prem ERP. Our AWS architecture builds a single Plant-to-P&L Digital Thread in five layers so every dollar of P&L variance traces back to a machine, work order, or supplier invoice within 24 hours.

Starting on the left in **Sources and Ingest**, shop-floor machines stream OPC UA telemetry through AWS IoT Greengrass over private VPN or Direct Connect into AWS IoT Core and Kinesis Data Streams On-Demand—sized for 20,000 messages per second at peak burst. From Kinesis, we split into two paths: Apache Flink detects anomalies and alerts cell leads via SNS in under 60 seconds, while Firehose micro-batches raw telemetry to S3. In parallel, DMS Serverless captures MES work-order CDC, AppFlow/Lambda pulls CMMS repair orders, Transfer Family SFTP ingests nightly ERP and CMM files, and Lambda fetches Open-Meteo weather, titanium and aluminum prices, USD/MXN FX rates, and SharePoint SOPs.

Two hard compliance boundaries anchor the design. First, Querétaro HR, payroll, and PII stay inside a dedicated Mexico account in `mx-central-1`, exporting only de-identified MXN GL rollups. Second, ITAR-controlled TALON data stays strictly in a dedicated US account in `us-east-1` with `us-west-2` DR—even when a TALON part like `P-1003` is machined at Querétaro, its MES work order routes directly to the US account and never touches Mexico.

In the **Lake**, raw data lands immutably in S3 Bronze with 7-year Object Lock for SOX finance. Glue ETL and Glue Data Quality convert Fahrenheit to Celsius, deduplicate telemetry and invoices, standardize labels, and quarantine bad records—like GL lines missing a cost center or duplicate AP invoices—instead of dropping them. Clean Silver entities conform into our **S3 Gold Apache Iceberg** star schema, which is AeroForge's single authoritative finance system of record, ready by 07:00 CT daily.

In **Serve and Insight**, Redshift Serverless reads Gold Iceberg tables in place—no second copy—powering QuickSight dashboards and our Bedrock AgentCore multi-agent Copilot. SageMaker predicts 48-hour failures into DynamoDB, Bedrock Knowledge Bases grounds responses in SOPs with Guardrails, and every AI-drafted P1 work order passes through a logged Human-in-the-Loop approval gate. The entire 3-plant pilot runs under $18,000 a month and scales cleanly to 12 plants plus Cimarron without re-architecture."

## 4. Ten Likely Professor Questions, Short Answers & Where to Point

1. **Why use Apache Iceberg in S3 Gold with Redshift Serverless reading in place instead of loading data into Redshift-managed storage?**
   - **Answer:** Keeping S3 Gold Iceberg as the single authoritative finance system of record avoids duplicating data into Redshift, provides ACID time-travel for SOX audits, and lets Redshift, Athena, and external read-in-place engines query the exact same tables without ETL drift.
   - **Where to point:** `l5_gold` (S3 Gold Iceberg), `sv1_redshift` (Redshift Serverless), and Flow `18` (`External Schema Read In-Place`).

2. **In the Data Pack, `WO-00005` runs TALON part `P-1003` at the Querétaro plant in Mexico. How does your architecture avoid violating either ITAR (`SOP-SEC-001`) or Mexico residency?**
   - **Answer:** The Mexico account (`mx-central-1`) holds only QRO HR, payroll, timecards, and PII; shop-floor MES CDC travels over private VPN/Direct Connect directly to `us-east-1`, where DMS routes TALON-part work orders straight into the dedicated US TALON account encrypted with KMS CMK #2.
   - **Where to point:** `b_mexico` (bullet 4), `s2_mes` -> `i4_dms` (Flow `6`), and `b_talon` (bullet 3).

3. **Why size Kinesis Data Streams for 20,000 msg/s when average enterprise throughput is only 480 msg/s?**
   - **Answer:** Simultaneous shift starts or chatter storms across 2,400 machines create sharp spikes (~41.7x average); Kinesis On-Demand absorbs 20,000 msg/s bursts without throttling or manual shard-splitting while billing primarily for actual usage during normal 480 msg/s periods.
   - **Where to point:** `i2_kds` (Kinesis Data Streams) and Flow `3` (`Stream (20K msg/s burst)`).

4. **How does the pipeline catch and handle the six deliberate Data Pack quality issues without losing financial records?**
   - **Answer:** Glue ETL and Glue Data Quality convert °F to °C via `temp_unit`, deduplicate telemetry and AP invoices, handle late/missing telemetry windows, standardize mismatched labels like `usd_per_kg` holding `USD_MXN`, and route GL lines missing a cost center and duplicate AP invoices to the S3 Quarantine bucket with SNS steward alerts rather than dropping them.
   - **Where to point:** `l2_glue` (Glue ETL + DQ), Flow `15` (`DQ Rejects`), `l3_quarantine` (S3 Quarantine Bucket), and `sv2_athena` / `in1_quicksight` (Flow `25` DQ Metrics).

5. **Why do you have anomaly detection in Managed Flink AND predictive maintenance in SageMaker AI?**
   - **Answer:** They solve different latency horizons: Managed Flink runs stateful Random Cut Forest checks on live Kinesis streams to fire shop-floor alarms within 60 seconds, whereas SageMaker trains imbalanced supervised models on historical Silver features and CMMS labels to predict failures 48 hours ahead.
   - **Where to point:** `i3_flink` + Flow `5` (`Under-60s Anomaly Alert`) versus `sv3_sagemaker` + Flow `20` and Flow `22` (`Live 48h Risk Scores`).

6. **How do you stop the Bedrock AgentCore Copilot from leaking TALON data to a non-US user or autonomously creating a bad P1 work order?**
   - **Answer:** AgentCore Identity propagates the caller's IAM Identity Center token (no standing permissions), so Redshift, Lake Formation (`program <> 'TALON'`), and Knowledge Bases filter out TALON data automatically; any drafted P1 CMMS work order is blocked by a mandatory Step Functions Human-in-the-Loop approval gate and logged to DynamoDB and CloudTrail.
   - **Where to point:** `in4_agentcore` (AgentCore Identity), `in3_kb` (KB Access Control & Guardrails), `in5_hitl` (HITL Approval), and Flows `28`, `30`, and `31`.

7. **How does the architecture handle Querétaro's MXN currency when `erp_gl_journal_lines.csv` only has `amount_usd` and the market API puts `USD_MXN` inside `usd_per_kg`?**
   - **Answer:** In enterprise operation, QRO exports de-identified MXN GL rollups across the Mexico export gate (`b_mexico`), and Glue ETL standardizes the `USD_MXN` field from `market_prices_api_sample.json` into a clean FX rate table to convert MXN to USD in Silver while retaining original MXN for auditability.
   - **Where to point:** `s5_ext` (`Commodity prices (Ti, Al) & USD/MXN FX`), `b_mexico` + Flow `11`, `l2_glue`, and `l4_curated`.

8. **How do you guarantee the 07:00 CT daily finance SLA and 7-year SOX audit compliance?**
   - **Answer:** ERP files arrive via Transfer Family SFTP at 23:00 CT, triggering Step Functions to run Glue DQ, Silver/Gold Iceberg updates, and Redshift materialized-view refreshes well before 07:00 CT; S3 Object Lock preserves raw finance files for 7 years, Iceberg supports time-travel queries, and `cc3_gov` enforces SOX segregation of duties across LF Admin, Pipeline Deployer, and Finance Approver roles.
   - **Where to point:** `s4_erp` + Flow `9`, `l1_raw` (7-Yr S3 Object Lock), `l5_gold` (07:00 CT SLA), `cc1_orch`, and `cc3_gov`.

9. **How does this stay under $18,000/month for the 3-plant pilot and still scale to 12 plants plus Cimarron (Site 13)?**
   - **Answer:** Every core tier is serverless or auto-scaled (Kinesis On-Demand, DMS Serverless, Glue Auto Scaling, Redshift Serverless with RPU cap and auto-pause, Athena scan limits, S3 lifecycle tiering), and `i6_cimarron` pre-allocates partition and catalog namespaces so adding plants 4–13 requires configuration, not re-architecture.
   - **Where to point:** `cc5_cost` (Cost Management & FinOps), `sv1_redshift` (RPU Cap & Auto-Pause), `i2_kds` (On-Demand), and `i6_cimarron`.

10. **What happens if a plant loses internet connectivity or `us-east-1` goes down?**
    - **Answer:** Greengrass gateways spool telemetry locally for 15 minutes at the plant to protect the 15-minute telemetry RPO; inside AWS, all ingestion and serving tiers run Multi-AZ, and S3 Cross-Region Replication plus AWS Backup replicate US and TALON data to `us-west-2` to meet the 4-hour telemetry and 8-hour warehouse RTOs while keeping Mexico DR in-country.
    - **Where to point:** `s1_edge` (15m Local Spool), `b_talon` (`us-east-1 Primary / us-west-2 DR`), and `cc4_mon` (Monitoring, Observability & DR).
